# ADR 0005: Conformance corpus from an independent oracle; saturating storage-float encoding

Status: accepted. Date: 2026-10.

## Context

spec/primitives.md states every primitive's result as the exact result
rounded to the output dtype, with per-operation tolerances. Without test
vectors those rules are only prose: two runtimes can each pass their own
tests and still disagree, and the Go reference code would become the de
facto spec by accident.

Writing the generator also exposed a gap. spec/primitives.md section 5.8
defers conversions to storage floats to spec/dtypes.md, but spec/dtypes.md
defined only the decode direction. A runtime had no rule for what
`cast(f32 -> f8_e4m3)` does with 1000.0 or infinity.

## Decision

- The conformance corpus (spec/conformance.md) is generated by
  `tools/gen_conformance.py`, an oracle written from the spec text in
  Python that shares no code with the Go kernels. Exact operations are
  computed in rational arithmetic, transcendental ones with mpmath at 256
  bits, and every result is rounded once to the output dtype. The corpus is
  committed, and CI checks that the generator reproduces it.
- The corpus records the comparison rule with each case (`bits`, `exact`,
  `ulp`, `tol`), so that a runtime in any language can check itself
  without re-deriving the tolerance table.
- The Go reference kernels (package `ref`) must pass every case in IEEE
  mode. A disagreement is resolved by reading the spec, never by
  regenerating the corpus from the Go code.
- Encoding to storage floats (spec/dtypes.md section 2.3) rounds to nearest
  even and saturates finite overflow to the largest finite value.
  Infinities stay infinite in `f8_e5m2` and saturate in `f8_e4m3`, which
  has no infinity. Saturation is the useful behaviour for quantized
  activations and weights and matches ONNX `Cast` with `saturate=1`;
  producing NaN for an out-of-range finite value would poison a whole
  tensor.

## Consequences

- The corpus is the conformance test for third-party runtimes: they load
  the JSON files and compare their results with the stated rules.
- The tolerance numbers in spec/primitives.md now have tests behind them.
  Tightening or loosening one is a spec change that regenerates the corpus.
- Storage floats as operands of `where` and `bitcast` were left out of the
  first corpus, because spec/primitives.md section 2.2 forbade them while
  sections 5.9 and 5.23 allowed them. v0.1 settles this by allowing them
  (both operations copy bits and do no arithmetic), and the corpus covers
  them.
