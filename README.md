# mmf

mmf (working name) is an open file format for machine learning models. It
aims to compete with ONNX and GGUF: smaller to implement, faster to load, and
able to hold any model, from a CNN to an LLM, for inference and for training.

> **Status: spec v0.1 draft, with a Go reference reader and writer.** The
> design rationale is in [docs/design-notes.md](docs/design-notes.md) and
> [docs/adr](docs/adr); the normative text is in [spec](spec).

## In one paragraph

A model file is a binary container: a 64-byte preamble, a binary index, a
graph written in 33 primitive operations, typed metadata, and the weights in
a page-aligned, memory-mappable region. A standard library defines hundreds of
common operations (GELU, softmax, layer norm, attention) as compositions of
the primitives, each with a name and version so a runtime with a faster
kernel can use it. A runtime that implements the 33 primitives runs every
model. Block-quantized dtypes are specified byte for byte, and the file is
treated as untrusted input throughout.

## Using the Go package

```go
f, err := mmf.Open("model.mmf")   // mmap, validate, no copies
defer f.Close()
t, _ := f.Tensor("layers.0.attn.q.weight")
data := f.TensorData(t)           // a slice into the mapping
g, err := f.Graph()               // decoded, validated graph
```

Writing:

```go
w := mmf.NewWriter()
w.AddTensor("w", mmf.F32, []uint64{2, 3}, bytes)
w.AddSection(mmf.SectionGraph, true, graphBytes)
w.WriteFile("model.mmf")          // temp file, fsync, rename
```

Run `go test ./...` for the test suite, including a hostile-file corpus,
fuzz targets for the container, metadata and graph parsers, and the
primitive conformance corpus run against the reference kernels.

## Conformance

The corpus in `testdata/conformance/primitives` holds 1,322 cases covering
all 33 primitives. Expected results come from an independent oracle that
evaluates the spec's definitions exactly (rational arithmetic, or mpmath at
256 bits) and rounds once to the output dtype, so the spec rather than the
Go code is the source of truth. A runtime in any language can load the JSON
files and check itself; see [spec/conformance.md](spec/conformance.md). From
Go:

```go
cases, _ := conformance.LoadDir("testdata/conformance/primitives")
report := conformance.Run(cases, ref.Eval, conformance.IEEE)
```

## Importing GGUF and safetensors

```
go run ./cmd/mmf-import -bench model.gguf                 # writes model.mmf
go run ./cmd/mmf-import -o model.mmf shard-1.safetensors shard-2.safetensors
```

Tensors are copied without re-quantization: every GGUF block type mmf
defines (Q4_0, Q8_0, Q4_K, Q6_K, MXFP4) has the same layout in both formats,
so a quantized tensor decodes to the same bits. GGUF types mmf does not yet
define (Q5_K, the IQ types, and others) are rejected by name. Metadata keys
keep their names and types. Neither source format carries a usable graph, so
the output holds weights and metadata only. `-bench` reports the size of
each file and the time to open it and read every tensor byte.

## Running a graph

```go
p, err := interp.Load(f)                 // f from mmf.Open
s := p.NewSession()                      // holds variables, such as a KV cache
out, err := s.Run(map[string]*ref.Tensor{"x": x})
```

`interp` binds symbolic dimensions from the inputs, runs `while`, `if` and
model-local composites, and applies variable updates atomically after each
run. Of the standard library it runs `matmul.v1`, `linear.v1`, `softmax.v1`,
`rms_norm.v1`, `exp.v1`, `sigmoid.v1`, `silu.v1` and `embedding.v1` by
evaluating their canonical bodies on the primitive kernels; other composites
are reported as unsupported. It favours clarity over speed and is meant for
checking other runtimes, not for serving models.
